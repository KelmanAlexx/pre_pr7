# Руководство оператора

**Программа:** «Умный кампус — менеджер ролей операторов»  
**Версия:** 1.0  
**Платформа:** Windows 10/11 x64, .NET 8  
**Назначение документа:** описание работы с учебной утилитой управления списком ролей.

## 1. Назначение и условия применения программы

Программа предназначена для получения демонстрационного списка пользователей из API, просмотра записей, назначения локальных ролей, фильтрации списка и сохранения таблицы доступов в формате CSV.

Программа применяется в учебном стенде ИС «Умный кампус» на рабочем месте оператора или администратора. ReqRes используется как внешний тестовый источник.

Для работы нужны:

- Windows 10 или Windows 11, 64-разрядная версия;
- установленный .NET 8 Runtime (для запуска опубликованной сборки);
- доступ в интернет по HTTPS через исходящий TCP-порт 443;
- действующий ключ API в переменной окружения `REQRES_API_KEY`;
- право записи в папку `C:\ProgramData\SmartCampus\Reports` (ее заранее создает администратор и выдает группе операторов минимальные права изменения).

Порт TCP 4317 используется не самой утилитой, а возможным сервером сбора телеметрии OpenTelemetry (OTLP/gRPC). Его разрешают только при наличии такого сервера и только от рабочего места к указанному адресу коллектора.

## 2. Подготовка к работе (вход и выбор роли)

### 2.1. Вход в рабочую среду

1. Включить компьютер и войти под личной учетной записью Windows.
2. Убедиться, что дата и время компьютера установлены правильно.
3. Проверить подключение к локальной сети и Интернету.
4. Запустить программу `SmartCampusRoleManager.exe` или выполнить `dotnet run` из папки проекта.

В данной версии отдельная форма авторизации не реализована. В реальной ИС вход должен выполняться по персональной учетной записи, а доступ к операциям должен определяться сервером авторизации. Нельзя использовать общую учетную запись нескольких операторов.

### 2.2. Подготовка ключа API

Ключ не записывается в `appsettings.json`, исходный код, CSV-файл или журнал.

Для временной установки ключа в PowerShell:

```powershell
$env:REQRES_API_KEY = "КЛЮЧ"
```

Для постоянной переменной текущего пользователя:

```powershell
[Environment]::SetEnvironmentVariable("REQRES_API_KEY", "КЛЮЧ", "User")
```

После создания постоянной переменной нужно закрыть и снова открыть терминал или программу. Не передавайте ключ другим пользователям и не помещайте его в снимки экрана.

### 2.3. Выбор роли

После загрузки пользователей оператор может назначить одной из записей роль: «Администратор», «Оператор проходной», «Сотрудник столовой», «Преподаватель» или «Не назначена».

Перед изменением роли администратора в производственной системе требуется согласование ответственного сотрудника.

## 3. Пошаговые сценарии работы

### 3.1. Загрузка списка пользователей

1. В главном меню выбрать пункт `1`.
2. Дождаться сообщения `[OK] Получено пользователей`.
3. При успешной загрузке программа заменит текущий список данными, пришедшими от API.
4. Если появилось сообщение об ошибке доступа, проверить ключ `REQRES_API_KEY`.

### 3.2. Просмотр списка

1. Выбрать пункт `2`.
2. На экране отображаются ID, ФИО, электронная почта и назначенная роль.
3. Если список пуст, сначала выполнить загрузку.

### 3.3. Назначение роли

1. Выбрать пункт `3`.
2. Ввести ID пользователя из списка.
3. Ввести номер подходящей роли.
4. Проверить сообщение об успешном изменении локальной записи.
5. При ошибочном ID или номере роли программа не должна изменять данные.

### 3.4. Фильтрация

1. Выбрать пункт `4`.
2. Ввести номер роли из предложенного списка.
3. Проверить отображенные записи и их количество.
4. Для просмотра всего списка выбрать пункт `2`.

### 3.5. Экспорт таблицы доступа

1. Назначить необходимые роли.
2. Выбрать пункт `5`.
3. Получить путь к сформированному файлу CSV.
4. Открыть файл в Microsoft Excel или совместимом табличном редакторе.
5. Проверить количество записей, роли и дату формирования.

Имя файла содержит дату и время, например `Таблица_доступов_20261031_153000.csv`. В CSV используется разделитель `;` и кодировка UTF-8.

## 4. Регламентные проверки и завершение смены

В начале смены оператор проверяет сетевое подключение, доступность API и наличие корректного ключа. После загрузки он сравнивает количество полученных записей с сообщением программы и сообщает администратору о пустом или неожиданном списке.

Перед экспортом нужно убедиться, что роли назначены согласно распоряжению ответственного лица. После экспорта следует открыть файл и проверить его читаемость. Отчет сохраняется в папке `C:\ProgramData\SmartCampus\Reports`. Каталог находится отдельно от папки установки программы, чтобы оператору не требовалось право изменения файлов в `Program Files`. Не следует хранить CSV в общедоступной папке или пересылать его через незащищенные каналы.

Для завершения работы выбрать пункт `0`, убедиться, что программа сообщила о завершении, и закрыть окно.

## 5. Аварийные ситуации и действия при сбоях (Troubleshooting)

| Сообщение или ситуация | Возможная причина | Действия оператора |
|---|---|---|
| Не задан ключ ReqRes API | Переменная `REQRES_API_KEY` отсутствует | Проверить переменную окружения, открыть новую сессию терминала и повторить загрузку |
| Ошибка доступа 401/403 | Ключ неверный, отозван или не передается | Проверить ключ, задать его заново; не записывать ключ в конфигурационный файл |
| Время ожидания ответа истекло | Нет Интернета, медленное соединение или сервер не отвечает | Проверить сеть, повторить запрос через несколько минут; при повторении сообщить администратору |
| Ошибка сетевого соединения | DNS, прокси, межсетевой экран или TLS | Проверить разрешение имени `reqres.in` и исходящий TCP 443; не отключать защиту самостоятельно |
| Ответ пустой или имеет неверный формат | Изменился ответ API либо источник вернул пустой набор | Не назначать роли на основании неполного списка; сохранить текст ошибки и обратиться к администратору |
| Нет прав на запись в папку отчетов | Недостаточно прав Windows или папка защищена | Проверить права на `C:\ProgramData\SmartCampus\Reports`; попросить администратора выдать минимально необходимые права изменения |
| CSV не открывается корректно | Неверный разделитель или кодировка при импорте | В Excel выбрать импорт из текста/CSV, кодировку UTF-8 и разделитель `;` |
| Пользователь не найден | Введен неверный ID или список обновился | Повторно открыть список и проверить ID |

При любом сбое оператор не должен отключать антивирус, межсетевой экран или проверку сертификатов. Если данные кажутся неполными или противоречивыми, следует прекратить назначение ролей и сообщить ответственному администратору.

## 6. Сообщения оператору

- `[OK] Получено пользователей` — список загружен; можно просматривать и фильтровать записи.
- `Не задан ключ API` — ключ отсутствует; загрузка не выполнена.
- `Ошибка доступа к API (401/403)` — сервер не разрешил запрос; проверить ключ.
- `Список пуст` — загрузка еще не выполнена или сервер не вернул пользователей.
- `[OK] Таблица сохранена` — CSV сформирован и записан в указанную папку.
- `Работа программы завершена` — приложение закрывает рабочий цикл.
